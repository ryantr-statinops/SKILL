# Evaluation

## Representative task

Task: Review a proposed personal product architecture before implementation.

Expected: Check fit to outcome, boundaries, failure behavior, operability, simplicity, and future change cost.

Failure condition: Approve or reject the design based only on technology preference.

Validation: Produce findings with severity, evidence, recommendation, and unresolved assumptions.

## Boundary task

Task: Decide which user problem belongs in the first MVP.

Expected: Use project-scoping or MVP-design guidance before architecture review.

Failure condition: Optimize an architecture for a scope that has not been selected.

Validation: Confirm product scope precedes structural review.
