# MVP design

## When to use
Use when turning a project idea into the smallest usable validation product.

## Personal principles
Optimize for learning and usable feedback, not a long feature checklist.

## Workflow
1. Identify the core assumption and target user action.
2. Map the smallest end-to-end path.
3. Remove features that do not test the assumption.
4. Define acceptance, instrumentation, and follow-up decisions.

## Decision rules
Prefer a narrow complete loop over a broad incomplete platform.

## Constraints
Keep infrastructure and abstractions proportional to validated demand.

## Failure modes
If the MVP cannot produce evidence, reduce or redesign the loop.

## Expected output
Produce MVP scope, user flow, exclusions, metrics, and next decision.

## Validation
The MVP can be demonstrated end-to-end without hidden manual work.
