# Evaluation

## Representative task

Task: Turn a broad personal product idea into an MVP that tests its riskiest assumption.

Expected: Define one user outcome, smallest workflow, success signal, non-goals, and learning plan.

Failure condition: Call a feature collection an MVP without a testable assumption.

Validation: Review the MVP statement and confirm a user can complete the intended outcome.

## Boundary task

Task: Harden an existing service after a production incident.

Expected: Route to debugging, security, or release guidance rather than MVP design.

Failure condition: Remove reliability work because it does not create a new feature.

Validation: Confirm the incident's operational outcome is preserved.
