# Brainstorming

## When to use
Use when an idea is early, ambiguous, or has multiple plausible directions.

## Personal principles
Separate exploration from commitment and make uncertainty visible.

## Workflow
1. State the question and constraints.
2. Generate distinct options without premature dismissal.
3. Cluster, compare, and identify assumptions.
4. Select a small experiment or decision checkpoint.

## Decision rules
Prefer an actionable experiment over an abstract list of ideas.

## Constraints
Do not silently convert brainstormed ideas into commitments.

## Failure modes
If the problem is not understood, return questions rather than fake certainty.

## Expected output
Produce options, trade-offs, selected direction, and next experiment.

## Validation
The next step is small, observable, and reversible.

## Agent handoff

- Selected when: Use when the requested outcome matches this skill description and workflow.
- Do not activate when: Do not activate when the task matches the stated exclusion or a narrower skill.
- Expected output: Produce the observable artifact, decision, or result described by the workflow.
- User-facing report: Summarize scope, result, checks, and unresolved risks.
- Confirmation boundary: Ask before destructive, external, or irreversible actions.
