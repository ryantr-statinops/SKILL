# Evaluation

## Representative task

Task: Select a backend language and storage option for a small personal service with limited maintenance time.

Expected: Compare requirements, team familiarity, ecosystem, operational cost, and reversibility before recommending an option.

Failure condition: Pick a technology solely because it is popular or technically interesting.

Validation: Check that the recommendation includes assumptions, rejected alternatives, and a reversible first step.

## Boundary task

Task: Choose a library after the project has already fixed its language and deployment constraints.

Expected: Use the repository's dependency-management workflow rather than reopening the entire technology selection.

Failure condition: Replace the platform decision without a new requirement.

Validation: Confirm the response remains at library scope.
