# Scope control

## When to use
Use when a project request grows beyond its stated outcome or adds unrelated complexity.

## Personal principles
Protect the smallest useful outcome and make deferrals explicit.

## Workflow
1. Compare the new request with the current goal.
2. Classify it as required, enabling, experiment, or future idea.
3. Estimate impact on time, complexity, and validation.
4. Accept, defer, split, or reject with rationale.

## Decision rules
New work must earn its place by improving the current outcome or reducing a proven risk.

## Constraints
Do not hide deferred work; record it separately.

## Failure modes
If priority is unclear, surface the trade-off instead of expanding silently.

## Expected output
Return updated scope, exclusions, deferred ideas, and decision rationale.

## Validation
The current milestone remains demonstrable and its acceptance criteria remain clear.
