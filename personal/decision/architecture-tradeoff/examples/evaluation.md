# Evaluation

## Representative task

Task: Compare a simple single-service design with a more distributed design for a personal product with uncertain growth.

Expected: Make trade-offs explicit across complexity, reliability, cost, and changeability, then recommend the smallest defensible option.

Failure condition: Choose an architecture from fashion or imagined scale without stating assumptions.

Validation: Review the decision table and confirm every recommendation is tied to a stated constraint.

## Boundary task

Task: Implement a specific bug fix inside an already-approved architecture.

Expected: Do not activate architecture trade-off guidance unless the fix changes a material system boundary.

Failure condition: Expand a local implementation task into an architecture redesign without evidence.

Validation: Confirm the response stays within the bug-fix scope.
